# Phase 3: AWS baseline and runbook

Records phases 4 and 5 of the index. `infra/aws/` describes the environment; `docs/backend-deployment.md`
is how a person brings it up and what to do when it misbehaves.

## Shape

Nine `.tf` files plus a committed `.terraform.lock.hcl`, locked for `linux_amd64`, `darwin_arm64`
and `darwin_amd64` so the Product Owner's Mac and the provider checksums agree on first `init`.

| File | Holds |
|---|---|
| `network.tf` | VPC, two public and two private subnets, gateway, three security groups |
| `registry.tf` | ECR with immutable tags and a 30-image lifecycle rule |
| `database.tf` | RDS PostgreSQL, generated credentials, Parameter Store SecureStrings |
| `load-balancer.tf` | Internet-facing ALB, target group, HTTP listener |
| `iam.tf` | Task execution role, task role, GitHub OIDC provider and deploy role |
| `service.tf` | Log group, ECS cluster, task definition, service |

## Decisions that are not obvious from reading the resources

**Tasks in public subnets, not behind NAT.** A NAT gateway is a fixed monthly charge larger than
the rest of this stack combined, and the task needs outbound internet only to pull its image and
reach Google's JWKS endpoint. It does not weaken isolation, because reachability is decided by
security groups, not by subnet: nothing may open a connection to a task except the load balancer,
and nothing to the database except a task. The database sits in the private subnets, which keep the
default route table and therefore have no internet route at all, with `publicly_accessible = false`.
The architecture's rule that cost control must not expose PostgreSQL publicly is met by three
independent facts rather than one setting.

**Every rule names a security group, never a CIDR**, except the one deliberately public ingress on
port 80. A permission that follows the resource cannot later be inherited by whatever else ends up
at an address.

**Secrets reach the container through `secrets`, never `environment`.** Values in `environment` are
returned in plain text by `describe-task-definition`, which the deploy job calls on every run.
`POSTGRES_PASSWORD` and `RIKKAUS_JWT_SECRET` are generated by the `random` provider, stored as
SecureStrings under `/rikkaus/<environment>/`, and resolved by the ECS agent at start-up. The
execution role's read grant is scoped to that prefix, so a Development task cannot read a Testing
parameter. No output exposes a secret.

**Google's client id and secret are optional.** Until issue #42 merges there is no sign-in to
configure, and a public PKCE client legitimately has none. Parameter Store rejects an empty
SecureString, so these are conditional resources rather than defaulted ones, and the task simply
receives no such variable when they are unset.

**`iam:PassRole` is the bound on `RegisterTaskDefinition`.** That action takes no resource
condition, which is an IAM limitation rather than a choice. Scoping PassRole to this environment's
two task roles means the permission cannot be used to run a task as a more privileged identity.

**Three `lifecycle` blocks, all for the same reason.** The task definition ignores
`container_definitions`, and the service ignores `task_definition` and `desired_count`, because the
pipeline and whoever scales the environment down between test windows own those. Without them the
next `tofu apply` would revert the most recent deployment to the placeholder revision.

## Three defects found and fixed during self-review

Each would have surfaced only on a real apply, which is where reviewing the configuration as if it
were about to run earns its keep.

1. **The first apply would have hung.** `wait_for_steady_state = true` on the service, combined
   with a placeholder image that by design never becomes a healthy target, means waiting until the
   timeout and then failing an apply that had in fact succeeded. Removed; waiting for a rollout is
   the deploy job's responsibility, at the one moment a steady state is the expected outcome.
2. **The target group could never have been replaced.** `create_before_destroy` cannot work
   alongside a fixed `name`: the replacement is created while the original still holds the name and
   the apply fails on the collision. Removed, with a note that nothing in the block forces
   replacement anyway.
3. **The placeholder crash-looped.** `busybox` with no command exits immediately, so the window
   before the first deployment would have been spent restarting. It now sleeps, and the reason it
   is still an unhealthy target is written down.

## Known limitations, accepted rather than overlooked

- **No HTTPS.** The accepted decision for this environment. Traffic is unencrypted; Google refuses
  a plain-HTTP redirect URI, so the sign-in from issue #42 cannot be exercised here; and an HTTPS
  page cannot call an HTTP API, which the Expo web preview from issue #46 will hit. Recorded in
  `load-balancer.tf`, the runbook and `README.md`, all three stating the same thing.
- **State is local** and holds the generated database password and signing key in plain text. It is
  git-ignored. An S3 backend with locking is needed before a second operator applies.
- **Nothing was applied.** No AWS resource was created and no live URL was verified, per the
  accepted decision that the Product Owner applies. `tofu fmt -check` and `tofu validate` pass
  against provider `aws` 6.66.0; a `plan` needs credentials and has not been run.

## Documentation reconciled

`ARCHITECTURE_TECHNOLOGY_DECISIONS.md` section 8 recorded Jenkins as a Multibranch Declarative
Pipeline with a root `Jenkinsfile`. It now records GitHub Actions, with a dated amendment note
stating what changed, why, and that the stage list, branch policy and promotion-by-digest rule are
untouched — only the runner moved. The repository-layout tree and the reference links were updated
to match, and the credentials paragraph now describes OIDC federation rather than a Jenkins
credential store.

`README.md` claimed the backend had no CI/CD pipeline and that the API must not be exposed beyond
local development. The first is now false. The second is replaced with the precise version: this
preview is safe to expose today only because nothing is behind it — the reachable endpoints are
`/actuator/health`, `/api/v1/meta` and an error surface, all anonymous by design — and HTTPS is
required before identity or any domain endpoint is deployed there.
