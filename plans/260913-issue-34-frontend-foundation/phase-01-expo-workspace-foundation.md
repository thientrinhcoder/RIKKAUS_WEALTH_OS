# Phase 1: Expo workspace foundation

## Objective

Create `apps/mobile` as the first executable Expo SDK 57 frontend workspace with npm lockfile, strict TypeScript, web support, and foundation dependencies. This phase creates the project shape only; it does not implement domain UI or backend contracts beyond dependency readiness.

## Context Links

- Architecture frontend stack: `ARCHITECTURE_TECHNOLOGY_DECISIONS.md:61-83`
- Frontend rules and mobile-first constraints: `ARCHITECTURE_TECHNOLOGY_DECISIONS.md:84-92`
- Target repo structure: `ARCHITECTURE_TECHNOLOGY_DECISIONS.md:242-257`
- #34 backlog row: `RIKKAUS_WEALTH_OS_MVP_DELIVERY_BACKLOG.md:141-143`

## Requirements

- Use Node `>=22.13` to match Expo SDK 57's minimum Node baseline.
- Start from `npx create-expo-app@latest apps/mobile --template default --no-agents-md` if the flag is supported; if not, delete generated agent instruction files from `apps/mobile` before finalizing.
- Keep npm as the package manager and commit `apps/mobile/package-lock.json`.
- Preserve existing backend and root files unless specifically listed here.
- Enable strict TypeScript and typed Expo Router routes.

## File Inventory

| File or path | Action | Notes |
|---|---|---|
| `apps/mobile/package.json` | Create | Scripts for web, web export/build, lint, typecheck, test, and Expo dependency check. |
| `apps/mobile/package-lock.json` | Create | npm lockfile; no yarn/pnpm/bun lockfiles. |
| `apps/mobile/app.json` or `apps/mobile/app.config.ts` | Create/modify | Expo app config, web output, scheme, typed routes. |
| `apps/mobile/tsconfig.json` | Create/modify | Strict mode; preserve Expo defaults and aliases only if generated. |
| `apps/mobile/src/app/_layout.tsx` | Create/modify | Minimal router layout placeholder until Phase 2 providers are added; follows the generated Expo SDK 57 source layout. |
| `apps/mobile/src/app/index.tsx` | Create/modify | Temporary minimal route only; Phase 2 owns final health UI. |
| `apps/mobile/assets/**` | Create | Keep only assets generated by Expo that are required for startup. |
| `apps/mobile/eslint.config.*` or `apps/mobile/.eslintrc.*` | Create/modify | Use Expo-compatible linting without broad custom rules. |
| `apps/mobile/.env.example` | Create | Document the public local API base URL configuration. |
| `.gitignore` | Modify if needed | Add generated Expo/Metro/native/build artifacts and explicit lockfile/plan tracking exceptions. |

Do not create `apps/mobile/src/domain`, auth routes, tabs, drawer routes, native `ios/` or `android/` directories, backend files, Flyway migrations, or CI files.

## Risk Assessment

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Expo scaffold adds tabs/example complexity outside #34. | Medium | Medium | Delete example routes and keep one index route. |
| Package versions drift from SDK 57. | High | High | Prefer `expo install` for Expo-coupled packages and run `expo install --check`. |
| App libraries have peer dependency warnings under React 19. | Medium | Medium | Use stable Paper v5 and current TanStack/RHF/Zod releases; do not pin arbitrary stale versions. |
