## Cookie and header observations

- Every auth call (`dev-sign-in`, `refresh`, `logout`, `google`) carried `X-Rikkaus-Client: web` and was sent with credentials. Domain calls (`/assets/{id}`, `/auth/session`, `/settings/exchange-rate`) carried `Authorization: Bearer …` and **no** cookie and no client header.
- Sign-in and every renewal answered `Set-Cookie: rikkaus_refresh=<value>; Path=/api/v1/auth; Max-Age=2592000; Expires=…; HttpOnly; SameSite=Strict` (no `Secure` under `local`, as documented). The response bodies held `accessToken, tokenType, expiresInSeconds, user`, with **no `refreshToken`**.
- The browser jar held `rikkaus_refresh` with domain `localhost`, path `/api/v1/auth`, `httpOnly: true`, `sameSite: Strict`; `document.cookie` never exposed it.
- Logout answered `204` with `Set-Cookie: rikkaus_refresh=; Path=/api/v1/auth; Max-Age=0; Expires=Thu, 01 Jan 1970 00:00:00 GMT; HttpOnly; SameSite=Strict`, and the jar was empty afterwards.

## Defects found and fixed during the run

1. **The Google popup wrote to localStorage.** `expo-web-browser`'s web handoff stored `ExpoWebBrowserRedirectHandle` and `ExpoWebBrowser_RedirectUrl_*` while the popup was open, and the denied redirect never reached the app. The web flow now opens the popup itself and the `/auth/callback` page returns the URL over a same-origin `BroadcastChannel` (`google-popup.web.ts`). `expo-auth-session` still builds the PKCE request and checks `state`. TC-10 and TC-11 were re-run; storage stays empty.
2. **The asset route was unreachable in development.** Metro's dev server reserves the `/assets/` prefix, so the route moved to `/holdings/<assetId>`, under the Tài sản & Nợ destination.

## Not verified, and contract gaps

- **Real Google sign-in.** No Google OAuth client exists locally, so the flow is verified only up to the authorization redirect, and the callback branches were driven by hand-made redirects. Cancel detection polls `popup.closed`. If Google ever enforces a cross-origin opener policy on that page, the poll could report the popup as closed while it is still open; check this with a real client.
- **Native.** The `expo-secure-store` path and the native Google redirect (`rikkaus-wealth-os://auth/callback`) were not run on a simulator. Native Google also needs per-platform client ids and matching API redirect URIs.
- **Contract gap: new versus returning account.** `SessionResponse` does not say whether the account was just created. The app shows the first-login panel when no USD/VND rate is declared yet. A boolean such as `newAccount` on `/auth/google` would make this exact.
- **Contract gap: expired versus revoked.** Both answer `401 unauthorized` on `/auth/refresh`. The app infers the reason from timing: refused on start means "hết hạn", refused while in use means "kết thúc". A distinct problem type or reason would remove the guess.
- **Write denial** ("Không có thay đổi được lưu") has no screen yet, because no write form exists; the asset slice inherits the copy.
- **Deployment.** On separate `*.cloudfront.net` hosts, web and API are cross-site, so the `SameSite=Strict` cookie needs same-origin routing then. This is a known caveat, unchanged here.
